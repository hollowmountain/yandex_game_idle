# Deep Core

Веб-игра в жанре idle: копаешь вниз сквозь слои породы к ядру планеты.
Тапаешь — копаешь сам, покупаешь буры — копают за тебя, слои глубже дают дороже руду.

Сделана под публикацию на **Яндекс Играх**, но одна и та же сборка работает
и на западных порталах (Poki, CrazyGames, itch) без переделки.

- Чистый JavaScript + Canvas, **без движка и без зависимостей**
- Вся сборка ~45 КБ — грузится мгновенно, это напрямую снижает bounce rate
- RU / EN с переключением на лету
- Сохранение: облако Яндекса, если игра запущена там, иначе `localStorage`

## Как запустить

Игре нужен любой статический http-сервер (через `file://` не заработает
из-за ограничений браузера на localStorage).

В комплекте лежит сервер на голом PowerShell — он не требует ни Node, ни Python:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File serve.ps1 -Port 8412
```

Дальше открыть `http://localhost:8412`.

Любая альтернатива тоже подойдёт, если на машине что-то стоит:

```bash
npx serve .
```

## Структура

| Файл | Назначение |
|---|---|
| `index.html` | разметка, подключение скриптов |
| `css/style.css` | вся вёрстка, мобильный экран первым |
| `js/data.js` | **весь баланс**: слои, буры, улучшения, цены, формулы |
| `js/state.js` | состояние, покупки, офлайн-прогресс, престиж |
| `js/sdk.js` | обёртка над SDK Яндекс Игр с деградацией до заглушек |
| `js/render.js` | канвас: слои породы, ствол шахты, бур, искры |
| `js/ui.js` | HUD, вкладки, карточки покупок, модалка |
| `js/i18n.js` | все тексты RU/EN |
| `js/main.js` | игровой цикл, автосохранение, реклама |

**Крутить баланс — только в `js/data.js`.** Остальные файлы читают числа оттуда.

## Что держит темп игры

Ключевая величина — `hard` у слоя, твёрдость породы. Фактическая скорость
проходки считается как `мощность буров ÷ твёрдость`, и твёрдость растёт вместе
с ценой метра.

Без неё игра не работает вообще: мощность буров растёт неограниченно, а шкала
глубины конечна, поэтому верхние буры проходят её за секунды и весь поздний
контент становится недостижимым. Ровно это и было в первой версии — вся игра
проходилась за 2 минуты, а три бура из восьми не покупались никогда.

Отсюда же правило: **менять `rate` бура и `hard` слоя нужно вместе.** Проверять
после правок — прогоном, он ниже.

Тап считается как `max(сила кирки ÷ твёрдость, 0.15 × текущая скорость)`.
Нижняя граница нужна, чтобы нажатие не обесценилось в ноль на глубине, где
твёрдость измеряется миллионами.

## Проверка баланса

Открыть игру, в консоли браузера прогнать симуляцию нужного сценария — весь
игровой код уже загружен, движка симуляции не требуется. Текущие показатели:

| Сценарий | До первого ядра |
|---|---|
| чистый пассив | ~34 мин |
| 1 тап/с | ~33 мин |
| 3 тапа/с | ~23 мин |
| после 4 ядер | ~18 мин |

Все 10 буров покупаются в каждом сценарии. Минимум платформы — 10 минут
геймплея, так что запас примерно двукратный даже при активной игре.

## Как устроена монетизация

- **Полноэкранная реклама** — не чаще раза в ~3,5 минуты. Ограничение зашито
  внутри `sdk.js`. Показывать чаще нельзя: бьёт и по удержанию, и по самой
  ставке eCPM.
- **Реклама за вознаграждение** — кнопка «×2 добыча» на 4 часа. Игрок жмёт сам,
  потому что ему выгодно.

Доход в вебе считается как `общее время в игре ÷ 3 минуты × eCPM`, поэтому
главный рычаг — длина сессии, а не длина одной попытки.

## SDK Яндекса

Грузится **только когда игра действительно запущена внутри Яндекс Игр**
(проверка домена и referrer в `sdk.js`). Вне Яндекса подключать его нельзя:
он сыплет необработанными ошибками в консоль, а JS-ошибки — прямая причина
отказа модерации, и они же сломали бы игру на других порталах.

Отладочные флаги в адресной строке:

- `?ysdk` — принудительно подключить SDK
- `?nosdk` — принудительно не подключать
